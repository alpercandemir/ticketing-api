# Ticketing API

A secure, high-concurrency event ticketing and reservation REST API built with **Java 25** and **Spring Boot 4.0**.

## Features
- **JWT Authentication** with access + refresh token flow and Role-Based Access Control (Admin, Organizer, Customer).
- **Concurrency & Oversell Protection** using JPA `@Version` optimistic locking.
- **Idempotency** interceptor for safe reservation request retries (required `Idempotency-Key` header).
- **Rate Limiting** via Bucket4j (50 requests/minute per IP).
- **Audit Logging** with Spring AOP (`@AuditLoggable`) intercepting key actions.
- **H2 In-Memory Database** with Hibernate DDL auto-generation and seed data.
- **OpenAPI / Swagger UI** documentation built-in via Springdoc.

## Getting Started

### Prerequisites
- Java 25 or higher
- Maven 3.9.x

### Build & Run
```bash
mvn clean install
mvn spring-boot:run
```

The application starts on port `8080`.
The in-memory H2 database schema is generated by Hibernate on startup, and seed users are loaded from `data.sql`.

### Swagger / OpenAPI Documentation
Once the application is running, navigate to:
```
http://localhost:8080/swagger-ui.html
```
The raw OpenAPI spec is available at:
```
http://localhost:8080/v3/api-docs
```
**Note:** Obtain a JWT from `/api/auth/login` and inject it via the `Authorize` button in Swagger UI.

## Authentication Flow

### 1. Login
```http
POST /api/auth/login
Content-Type: application/json

{
  "email": "customer@example.com",
  "password": "password"
}
```

### 2. Response
```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOi...",
  "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOi...",
  "email": "customer@example.com"
}
```

### 3. JWT Payload Structure (decoded)
```json
{
  "sub": "customer@example.com",
  "iat": 1710259200,
  "exp": 1710345600
}
```
- `sub` — User's email (subject)
- `iat` — Issued-at timestamp (epoch seconds)
- `exp` — Expiration timestamp (access token: 24h, refresh token: 7d)

### 4. Using the Token
Include the access token in subsequent requests:
```
Authorization: Bearer <your-jwt-access-token>
```

### 5. Refreshing Tokens
```http
POST /api/auth/refresh
Content-Type: application/json

{
  "refreshToken": "<your-refresh-token>"
}
```
Returns a new `accessToken` and `refreshToken` pair.

## Core Endpoints

### Authentication
| Method | Path | Access | Description |
|--------|------|--------|-------------|
| POST | `/api/auth/register` | Public | Register a new user |
| POST | `/api/auth/login` | Public | Login, returns JWT tokens |
| POST | `/api/auth/refresh` | Public | Refresh token flow |

### Events
| Method | Path | Access | Description |
|--------|------|--------|-------------|
| POST | `/api/events` | Organizer/Admin | Create a draft event |
| PUT | `/api/events/{id}` | Owner/Admin | Update an event |
| POST | `/api/events/{id}/publish` | Owner/Admin | Publish a draft event |
| GET | `/api/events?ownerId=...` | Organizer/Admin | List events (optional owner filter) |
| GET | `/api/events/public?from=...&to=...&q=...` | Public | Discover published events |

### Reservations
| Method | Path | Access | Description |
|--------|------|--------|-------------|
| POST | `/api/events/{id}/reservations` | Customer/Admin | Reserve seats (requires `Idempotency-Key` header) |
| POST | `/api/reservations/{id}/confirm` | Owner/Admin | Confirm a pending reservation |
| POST | `/api/reservations/{id}/cancel` | Owner/Admin | Cancel and return capacity |

## Architectural Decisions

### Database Strategy
H2 in-memory database with Hibernate `ddl-auto: create`. The schema is derived directly from `@Entity` classes, keeping the entity definitions as the single source of truth. Seed data is loaded via Spring Boot's `data.sql` mechanism. This approach is ideal for a development/demo project; for production, a migration tool like Flyway would be layered in.

### Oversell Protection
Hibernate optimistic locking (`@Version` on `Event`). When concurrent transactions attempt to decrement the same event's capacity, only one succeeds — the rest receive an `ObjectOptimisticLockingFailureException` mapped to HTTP 409. The concurrency test proves that with 10 threads competing for 1 seat, exactly 1 succeeds and 9 fail.

### Idempotency
A generic `IdempotencyInterceptor` + `ResponseBodyAdvice` pair. The interceptor stores an `IN_PROGRESS` key before the request is processed, and the `ResponseBodyAdvice` updates it to `COMPLETED` with the serialized response. Subsequent requests with the same key return the cached response, preventing duplicate reservations.

### Audit Logging
An AOP aspect (`@AuditLoggable`) captures actor, action, resource type/ID, IP, and user-agent for key operations. This keeps audit concerns decoupled from business logic.

### Rate Limiting
Bucket4j filter at the servlet level, keyed by client IP address (50 requests/minute). Returns HTTP 429 when exceeded.

### Security
Stateless JWT authentication with Spring Security. `@PreAuthorize` annotations enforce role-based access at the controller level. Ownership checks (owner-or-admin) are enforced at the service level.

## Testing

Run tests with:
```bash
mvn test
```

### Test Coverage
- **Unit tests** — `ReservationServiceTest` (reservation logic), `EventServiceTest` (event CRUD, ownership), `AuthServiceTest` (registration, login, refresh).
- **Integration tests** — `ConcurrencyTest` (`@SpringBootTest` with H2) proves oversell protection under 10 concurrent threads.
- **Security tests** — `SecurityIntegrationTest` (MockMvc) verifies role-based access rules across endpoints.
